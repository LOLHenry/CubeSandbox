# Android 沙箱渲染：按需高帧率（材料稿）

> 本页提出问题并给出技术诉求方向。实现仍在验证。按需 / 快速两条并行，分由不同团队承担。

## 标题

Android 沙箱：AI Agent 基础设施之一，诉求按需高帧率渲染

## 1. 背景：Mobile GUI 训练的业务目标与业务问题

**业务目标：** 把 Mobile GUI Agent 训练做成可规模化的产线——同样预算、同样集群，尽量多开并行实验、尽量缩短一轮训练/评测的交付周期，加快模型迭代。

**业务场景：** Agent 在沙箱里循环「截图 → 决策 → 交互」。人要连续画面；Agent 只在截图那一下需要当前界面。

**业务问题：** 训练要的是**大规模并行路数**（千路量级 rollout）。Android 沙箱却走 CPU 软渲染（`gpu_mode=guest` / SwiftShader）。机器在 Agent 不看屏时仍在画屏，名义能开的路数开不满，一轮实验要排更久、单样本更贵。

## 2. CPU 渲染瓶颈对上述业务的影响（量化）

规格（catalog）：每路沙箱 **4 核 / 6GiB**，画面 **1080×1920**。内部画像：复杂界面软渲染 **CPU 热点 &gt;50%**，部分场景 **帧率 &lt;10fps**。

不要用「少空等」「卡了 2 个核」当业务结论。对领导只保留两件事：**并发规模少开多少**，以及 **截图慢算不算主因**。

### 2.1 主因：渲染空转 → 大规模并发开不满

决策期 Agent 不看屏，但软渲染仍按面向人的方式刷帧。内部热点 &gt;50%，即每路约一半配额（约 2 核）在画无人看的画面。公开评测里决策/规划可占逐步墙钟 75%～94%，空转发生在**大部分时间**。

算例（由 4 核规格 × 50% 热点推算，待集群实测校准）：

| 规模 | 名义并发（按 4 核/路） | 决策期花在无效渲染上的核 | 对并发规模的影响 |
| --- | --- | --- | --- |
| 单节点 64 核 | 16 路 | 约 32 核（节点的 **50%**） | 这 50% 核腾不出来给新路 |
| 目标 1000 路并行 | 需 4000 核 | 约 **2000 核** 在空转 | 同等算力大约少开 **30%～50%** 的路（量级：1000 路预算大约只能当 500～700 路用） |

**业务体验：** 不是「某两核很忙」，而是同样一批鲲鹏机器，并行实验规模少三到五成，排队变长、一周能训完的量变少、单样本成本升高。这是对「大规模并行训练」目标的主打击。

### 2.2 次因：出帧慢 → 单步多等 100ms～1s，不是主业务矛盾

&lt;10fps 时，凑齐一张稳定截图往往多等 **100ms～1s**。决策本身常是秒级，这一段相对单步墙钟**问题不大**，也不是领导要的「卡顿体验」。

要说对最终业务的影响，只能算到产线，不能停在单步：

- 100 万步 × 多等 0.3s ≈ 串行 83 小时；**100 路并行**仍大约多 **0.8 小时/轮**。
- 相对「并发少开 30%～50%」导致的墙钟翻倍风险，出帧等待是**次要项**。
- 复杂页若截图迟迟不齐，可能拖成无效样本，这一条尚无内部比例，不写进主结论。

**结论给领导：** 要打的业务账是并发规模（空转吃掉约一半核时）；截图慢要做，但不是因为 100ms 体验差，而是给快速渲染团队一个可优化的库瓶颈，避免复杂页把等待从百毫秒拖成秒级以上。

口径：50%、&lt;10fps、4 核为内部/catalog；75%～94% 为公开时延拆分；30%～50% 少开路数为推算量级，需用「节点可开路数 / 集群 CPU 利用率」实测替换。

## 3. 技术诉求：打开 CPU / SwiftShader 瓶颈

两条并行，分团队：按需打空转（要并发），快速打出帧（要截图齐）。

**基础库瓶颈 → 快速渲染团队**

- SwiftShader：Setup、光栅化、PixelRoutine、纹理采样与混合全在 CPU，1080p 复杂界面的热点多在这里。
- Skia / HWUI：DisplayList 回放、`saveLayer`/模糊、RenderThread 同步，把过量绘制灌进 SwiftShader。
- Reactor JIT：首帧编译贵；热路径未吃满鲲鹏 SVE/SVE2 时像素吞吐上不去。

**业务逻辑问题 → 按需渲染团队**

- 按人用的 vsync 持续合成，决策期无观测仍在刷。
- 默认全屏 1080×1920、动画未关、无脏区整帧重画。
- 截图整帧读回，和 Agent「只要一张稳定图」不匹配。

**诉求**

1. **按需渲染：** 非截图阶段减少无效渲染，把空转那一半核让出来，把大规模并发路数抬上去。  
2. **快速渲染：** 缩短 SwiftShader 出帧，保证截图期能拿到稳定帧（复杂页不要从百毫秒拖成数秒）。
