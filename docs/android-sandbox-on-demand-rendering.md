# Android 沙箱渲染：按需高帧率（材料稿）

## 标题

Android 沙箱：AI Agent 基础设施之一，诉求按需高帧率渲染

## 场景诉求

**按需高帧率渲染：** GUI Agent 在沙箱中「截图 → 决策 → 交互」，需在截图时高帧率出帧，非截图时按需减少渲染空转，进而提升密度、减少单步等待。

## 业务问题

GUI Agent 依据稳定后的截图进行决策，具体影响为：

**1. 截图阶段出帧慢：** 复杂界面软渲染热点占比可超过 50%，帧率低于 10fps，出帧慢导致 Agent 获得稳定截图的时间变长，单步等待时间增加。

**2. 非截图阶段渲染空转：** 非截图阶段的渲染过多占用 CPU，单机并发沙箱密度变少。

## 技术诉求

**按需高帧率渲染**

**1. 按需渲染：** 由控制面在决策期与截图期切换渲染档位，降低空转、提升单机并发。

- 决策期：暂停 vsync 或降到低刷新，跳过未变化图层的合成。  
- 截图期：恢复高刷新，取当前已合成完整帧，而不是等截图请求再从零绘制。  
- 档位由 Agent/控制面显式下发，沙箱不自行猜测是否在决策。

**2. 快速渲染：** 截图期尽快完成一帧合成；同等部署密度下缩短软渲染出帧时间。

- 多线程光栅化，绘制与合成流水线并行。  
- 热点算子向量化（如 NEON）。  
- 软渲染路径优化为主；有 GPU/硬件合成时优先走硬件，降低 CPU 占比。
